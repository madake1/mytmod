# 开发顺序与验收

目前优先让一个房间里的战斗、掉落、抽卡和出口流程成立，之后再扩展地图和装备数量。

## P0：恢复可运行基线

- 配好 stable 和 SDK，完成 Build + Reload，确认物品贴图、UI、三台机器 JSON 加载正常。
- 使用旧测试角色检查保底记录和定轨状态；退出重进后仍一致。
- 2026-10-31 已在 tModLoader v2026.08.3.0 与 .NET 8 SDK 8.0.427 编译，并在独立服务器加载、保存和重载冒险世界。抽卡完整流程与作者身份证的客户端操作仍需实测。

## P1：抽卡正确性与联机边界

下面是阅读现有代码发现的问题，本轮未重写玩法解决它们：

- **服务器信任客户端奖励**：GachaResult 包直接提供玩家编号、物品、数量、品质，whoAmI 未作为权威身份；正式联机前必须改为客户端只请求“机器、次数、定轨”，服务器校验位置、距离、货币和状态，计算奖励并发放，再同步结果与保底。
- **扣费不是事务**：当前先扣金球，再计算结果。非法配置或空池异常可能造成扣费但没有完整奖励。加载时验证配置，计算/校验完成后统一提交扣费、保底、发奖。
- **卡池物品合法性**：第三台机器包含 `SeafoamTrident`、`MeteoriteSword`，必须针对目标版本确认是否存在。当前反射找不到时返回 itemType 0，不能接受为有效奖励。
- **概率含义不明确**：同一个随机数先判断 goldChance，再判断 purpleChance，紫色实际区间会被金色占用；高金概率下可能没有紫色区间。明确概率表和优先级后再改算法，并测试第 10/80 抽及概率递增边界。
- **空池回退**：某些分支最终仍访问空池；回退奖励品质与实际奖池也可能不一致。
- **定轨靠列表索引和物品类型**：配置已有重复奖励，UI 使用 FindIndex 按类型查找，会命中第一个重复项。未来使用稳定 rewardId，设计旧索引迁移。
- **跨地图键冲突**：仅坐标作为机器 ID，无法区分不同地图的同坐标机器。引入地图 ID + machineId，并迁移旧存档。
- **状态生命周期**：补全配置卸载、静态物品映射重建、UI 关闭/切世界处理；不要依赖旧会话残留状态。

验收：货币不足不扣费不增加保底；1/10 抽完整发奖；无效池不扣费；存档重进一致；双客户端状态一致；伪造玩家、奖励、超量和远距离请求被服务器拒绝。服务器权威改造完成前，不把当前版本作为正式联机版本发布。

## P2：地图规则

内置大世界底图通过 `.wld` 自带的世界 GUID 和世界 ID 识别，可单文件分发；其他地图仍使用 ModSystem 的 `mapId`/`mapVersion`，需要 `.twld`。单人模式下作者身份证装备在功能饰品栏时可编辑；联机服务器暂不开放作者编辑。

下一步覆盖液体、特殊道具、地形改造弹幕和非标准放置入口；设定门、箱子、机关、火把、绳索等白名单。现有“打开抽卡 UI 就禁止使用物品”只是交互限制，已独立于冒险规则。

验收：游玩模式不能破坏设计地形，武器和允许道具正常使用；普通世界不误锁；制作模式可编辑；专用服务器不依赖客户端 UI 状态；换世界不泄漏规则。

## P3：做一个小地图闭环

完成出生点 → 战斗房 → 原石奖励 → 金球兑换/抽卡 → Boss → 出口。确定复活、存档点、刷怪、Boss 奖励重复领取规则，以及多人原石的分配方式。移除商人金球和低成本武器测试配方，或仅在明确的开发模式开启。

内置地图发布一个 `.wld` 及匹配版本说明。若后续在地图中放置模组方块、墙、物品或世界状态，需要重新评估 `.twld` 依赖；其他通过命令标记的地图仍要同时发布 `.wld` / `.twld`。限制外部角色带入装备与否需要单独设计，当前没有实现。
